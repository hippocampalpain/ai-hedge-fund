# 한국 모드: 데이터 출처와 계산식

코드 위치: `hedge_fund/data/kr/fundamentals.py` (계산), `hedge_fund/data/kr/accounts.yaml` (계정 매핑)

## 1. 기본 원칙

| 원칙 | 구현 |
|---|---|
| 미래 데이터 누설 금지 | 기준일 `D`에는 DART 접수일(`rcept_no` 앞 8자리 = `rcept_dt`)이 `D` 이하인 보고서만 읽는다. **계산하기 전에** 거른다. 아직 끝나지 않은 분기의 보고서는 요청하지도 않는다. |
| 값을 지어내지 않음 | 입력이 하나라도 없으면 결과는 `None`. 0으로 채우지 않는다. |
| 연결 우선 | 보고서마다 연결재무제표(CFS)를 먼저 찾고, 없으면 별도재무제표(OFS)를 쓴다. CFS와 OFS끼리는 절대 빼거나 더하지 않는다. |
| 통화 | 모든 금액은 원(KRW). `currency="KRW"`. |

## 2. 누적값 → 분기값

DART 가이드에 따르면 분기·반기 보고서의 손익계산서는 `thstrm_amount`가 3개월 금액, `thstrm_add_amount`가 누적 금액이다. 현금흐름표는 누적으로만 공시된다. 그래서 손익·현금흐름 항목은 **항상 누적 금액을 읽고** 빼서 분기 값을 만든다.

```
1분기 = 1분기보고서(11013) 누적
2분기 = 반기보고서(11012) 누적 − 1분기 누적
3분기 = 3분기보고서(11014) 누적 − 반기 누적
4분기 = 사업보고서(11011) 연간 − 3분기 누적
```

빼는 쪽 보고서가 없으면 그 분기의 손익·현금흐름은 `None`이다. 재무상태표 항목은 각 보고서의 기말 잔액을 그대로 쓴다.

## 3. TTM과 공시일

- **TTM(최근 12개월)** = 연속된 4개 분기의 합. 4개 중 하나라도 없으면 그 행은 만들지 않는다.
- **행의 `filing_date`** = 그 행을 만드는 데 쓴 보고서 중 **가장 늦은 접수일**.
- **평균 잔액** = (이번 분기말 + 4분기 전 분기말) ÷ 2. 4분기 전 값이 없으면 평균을 쓰는 지표는 `None`이다.
- **유통주식수**: DART 「주식의 총수 현황」의 유통주식수(발행주식 − 자기주식), 보통주+우선주 합계. 이 값은 반기·사업보고서에만 있고 1·3분기 보고서에는 `-`로 나온다. 그래서 1·3분기는 직전에 공시된 반기·사업보고서 값을 이어 쓴다.

## 4. 지표 계산식

| 지표 (필드) | 계산식 |
|---|---|
| EPS `earnings_per_share` | TTM 지배주주순이익 ÷ 유통주식수 |
| BPS `book_value_per_share` | 지배주주지분 ÷ 유통주식수 |
| PER `price_to_earnings_ratio` | 공시일 종가 ÷ EPS (EPS ≤ 0이면 None) |
| PBR `price_to_book_ratio` | 공시일 종가 ÷ BPS (BPS ≤ 0이면 None) |
| PSR `price_to_sales_ratio` | 공시일 종가 ÷ (TTM 매출 ÷ 유통주식수) |
| ROE `return_on_equity` | TTM 지배주주순이익 ÷ 평균 지배주주지분 |
| ROA `return_on_assets` | TTM 당기순이익 ÷ 평균 자산총계 |
| ROIC `return_on_invested_capital` | 영업이익 × (1 − 법인세비용/세전이익) ÷ (자본총계 + 차입금 − 현금성자산) |
| 부채비율 `debt_to_equity` | 부채총계 ÷ 자본총계 (배수. 네이버 % 값 ÷ 100) |
| `debt_to_assets` | 부채총계 ÷ 자산총계 |
| 유동비율 `current_ratio` | 유동자산 ÷ 유동부채 |
| 당좌비율 `quick_ratio` | (유동자산 − 재고자산) ÷ 유동부채 |
| `cash_ratio` | 현금및현금성자산 ÷ 유동부채 |
| `operating_cash_flow_ratio` | TTM 영업활동현금흐름 ÷ 유동부채 |
| 매출총이익률 `gross_margin` | 매출총이익 ÷ 매출 (매출총이익 계정이 없으면 매출 − 매출원가) |
| 영업이익률 `operating_margin` | 영업이익 ÷ 매출 |
| 순이익률 `net_margin` | 당기순이익(비지배 포함) ÷ 매출 |
| FCF | 영업활동현금흐름 − \|유형자산의 취득\| |
| `free_cash_flow_per_share` | FCF ÷ 유통주식수 |
| `free_cash_flow_yield` | FCF ÷ 시가총액 |
| 시가총액 `market_cap` | 공시일(또는 그 직전 거래일)의 KRX 시가총액 (보통주) |
| 차입금 | 단기차입금 + 유동성장기부채 + 장기차입금 + 사채 (있는 계정만 더함, 하나도 없으면 None) |
| EV `enterprise_value` | 시가총액 + 차입금 − 현금성자산 |
| EBITDA | 영업이익 + 감가상각비 (+ 무형자산상각비). 감가상각비가 현금흐름표 본문에 없으면 None (삼성전자는 주석에만 있어 None) |
| `enterprise_value_to_ebitda_ratio`, `enterprise_value_to_revenue_ratio` | EV ÷ EBITDA, EV ÷ TTM 매출 |
| `peg_ratio` | PER ÷ (EPS 성장률 × 100), 성장률 > 0일 때만 |
| 성장률 `*_growth` | 이번 TTM ÷ 4분기 전 TTM − 1 (기준값 ≤ 0이면 None) |
| `payout_ratio` | \|배당금 지급\| ÷ TTM 지배주주순이익 |
| 회전율 | 매출(재고는 매출원가) ÷ 평균 자산·재고·매출채권·운전자본. DSO = 365 ÷ 매출채권회전율 |
| `interest_coverage` | 영업이익 ÷ 이자비용 — 이자비용이 손익계산서 본문에 따로 있을 때만 (대부분 None) |

지배주주순이익이나 지배주주지분 계정이 없으면(별도재무제표 등) 당기순이익과 자본총계를 대신 쓴다.

## 5. KRX·네이버 값과 비교할 때 주의할 점

삼성전자, 기준일 2026-11-06, 2025년 사업보고서 행으로 검증한 결과:

| 항목 | 이 프로그램 | KRX 발표값 | 차이의 이유 |
|---|---|---|---|
| BPS | 63,997 | 63,997 | 일치 |
| EPS | 6,676 | 6,605 | 약 1%. KRX는 기간 **가중평균** 주식수, 이 프로그램은 **기말** 유통주식수 |
| PER | 28.15 (공시일 3/10 종가 기준) | 28.57 (11/6 종가 기준) | 가격 기준일이 다름 |

- KRX와 네이버의 PER은 "오늘 종가 ÷ 직전 사업연도 EPS"다. 이 프로그램의 PER은 "**공시일** 종가 ÷ TTM EPS"다. 백테스트에서 그 시점에 알 수 있던 값만 쓰기 위해서다.
- 그래서 비교할 때는 사업보고서 행(분기말 12-31)의 EPS·BPS를 KRX 값과 맞춰 보면 된다.

## 6. 데이터 출처와 대체 순서

| 데이터 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| 일봉·시가총액 | pykrx (KRX 로그인 필요, `adjusted=False` = 수정 전 주가) | FinanceDataReader (네이버, 수정주가) | FDR GitHub 일별 스냅샷 (2026년 3월 이후만) |
| KOSPI 지수 | pykrx (지수코드 1001) | FDR `KS11` (GitHub 캐시) | — |
| 재무제표·주식수·임원소유보고·결산월 | OpenDART | — | — |
| 종목명·업종 | FDR `KRX-DESC` 목록 (하루 캐시) | DART 고유번호 목록 (이름만) | — |

한 경로가 실패하면 다음 경로를 시도한다. 모든 경로가 실패하면 빈 값이 아니라 **오류를 낸다**. "데이터 없음"과 "접속 실패"를 구분해서, 백테스트가 실패를 "신호 없음"으로 잘못 읽지 않게 하기 위해서다.

캐시는 `~/.hedge-fund/cache/kr/` 아래에 있다 (Windows: `C:\Users\<이름>\.hedge-fund\cache\kr\`).
- DART: 공시된 보고서는 영구 보관. "아직 없음"(013)은 최근 2년 이내 연도면 하루 뒤 다시 묻는다.
- 시세: 연도 단위로 저장.
- DART 호출 간격은 기본 0.3초(`DART_MIN_INTERVAL`). 실패하면 2초, 4초, 8초 간격으로 재시도한다.

## 7. 클라우드에서 필요한 네트워크 도메인

| 도메인 | 용도 | 이 세션 상태 |
|---|---|---|
| `opendart.fss.or.kr` | DART API | 허용됨 |
| `data.krx.co.kr` | pykrx 로그인과 KRX 데이터 (HTTPS) | 허용됨 |
| `raw.githubusercontent.com` | FDR: KOSPI 지수 캐시, 종목 목록, 일별 스냅샷 | 허용됨 |
| `generativelanguage.googleapis.com` | Gemini | 허용됨 |
| `fchart.stock.naver.com` | FDR 개별 종목 주가 (2순위 경로) | **차단됨** (선택 사항) |

pykrx의 수정주가 경로(`http://fchart.stock.naver.com`)는 평문 HTTP라서, HTTPS만 지원하는 클라우드 프록시로는 도메인을 허용해도 쓸 수 없다. 그래서 이 프로그램은 그 경로를 쓰지 않는다.

## 8. 한계 (1차 버전)

- **12월 결산 법인만 재무지표를 제공한다.** 다른 결산월이면 빈 목록을 돌려주고 경고를 남긴다(분기 해석을 추측하지 않기 위해).
- **뉴스는 제공하지 않는다.** **실적 서프라이즈(컨센서스)도 무료로 구할 수 없어서** PEAD 모델은 한국에서 항상 중립이다.
- **정정공시:** DART 전체 재무제표 API가 정정 후 숫자를 돌려주는 경우, 원래 공시일 기준으로 아주 약간의 누설이 있을 수 있다.
- **주가 기준이 섞일 수 있다:** pykrx는 수정 전 주가, FDR(네이버)은 수정주가다. 액면분할이 있었던 종목은 경로에 따라 과거 가격 기준이 다를 수 있다.
- **업종 정보는 최신값을 쓴다** (과거 시점 값이 아님. 미국 모드와 같은 근사).
- **분 단위 펀드는 지원하지 않는다**(일봉만).
- **시가총액 분위표:** 미국 달러 기준 표라서 한국 모드에서는 쓰지 않는다. 블라인드 프롬프트에 크기 정보가 나오지 않는다.
- **TUI 화면의 `$` 표기는 그대로다** (금액은 원화).
